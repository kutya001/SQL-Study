# Разработка и публикация

## Что нужно

- Браузер Google Chrome или Microsoft Edge (в Firefox и Safari курс работает, но без режима «в папке»).
- [Node.js](https://nodejs.org/) 18+ — для проверок и сборки `schemas/index.js`. Зависимостей нет, `npm install` не нужен.
- Python 3 — только если хотите открыть курс через локальный веб-сервер.

## Запуск

```bash
# вариант 1 — прямо из папки
откройте index.html двойным щелчком

# вариант 2 — как на сайте (http)
python3 -m http.server 8000
# → http://localhost:8000
```

Адреса `localhost` и `127.0.0.1` курс считает «своей папкой» (как `file://`). На любом другом адресе он работает в режиме сайта (`Store.hosted`): выбранная папка — только место для файлов прогресса, учебные базы берутся с сайта.

## Инструменты — `tools/`

| Команда | Что делает |
|---|---|
| `node tools/validate-course.js [m03]` | основной курс: выполняет все примеры, эталоны задач, ДЗ, тренажёр и справочник; проверяет уникальность id, ответы вопросов, варианты `wrong`/`alsoOk` |
| `node tools/validate-packs.js [sewing]` | все учебные базы из `schemas/` (или одну): загрузка, типы и связи в CSV, все задания, примеры, уроки. `HIDDEN=1` — вместе с `_шаблон` |
| `node tools/check-pack.js путь/к/базе` | одна база из любой папки — удобно до того, как класть её в `schemas/` |
| `node tools/test-engine.js` | самопроверка движка: короткие запросы с известным результатом SQL Server (типы, NULL, сортировка, ошибки по номерам). При исправлении движка добавляйте сюда случай |
| `node tools/validate-guide.js` | подсказки и экскурсии (`content/guide.js`): структура, метки элементов есть в коде, значки и адреса существуют |
| `node tools/build-index.js` | пересобрать `schemas/index.js` (меняется, только если базы изменились); `--check` — только проверить актуальность |
| `node tools/sql.js <база> "SELECT …"` | выполнить запрос к учебной базе в консоли (`-f файл.sql` — из файла) |
| `node tools/generators/gen_shop.js` | пересоздать CSV базы из генератора (также `gen_sewing.js`, `gen_cargo.js`); генераторы детерминированные |
| `npm run check` | все проверки сразу (курс, базы, движок, подсказки, актуальность `index.js`) |
| `python3 tools/ui-smoke.py` | проверка интерфейса в настоящем браузере: сайт (http) и папка (file://), вход, задача, базы, песочница, таблица результата, схема на canvas, фильтр тренажёра, сохранение. Нужен `pip install playwright` и `python -m playwright install chromium` |

Все проверки должны проходить **без ошибок**. Замечания (например, «эталон возвращает 0 строк», «TOP без ORDER BY») нужно разобрать: иногда это нормально, но чаще — ошибка в задаче.

## Типичные задачи

**Новая учебная база.** Скопируйте `schemas/_шаблон` в `schemas/<id>`, заполните по [ФОРМАТ.md](../schemas/ФОРМАТ.md) (или поручите ИИ по скиллу [sql-kurs-uchebnaya-baza](../skills/sql-kurs-uchebnaya-baza/SKILL.md)). Затем:

```bash
node tools/check-pack.js schemas/<id>
node tools/build-index.js
```

**Новый урок или задача основного курса.** Формат — [КОНТЕНТ.md](КОНТЕНТ.md), скилл — [sql-kurs-uroki](../skills/sql-kurs-uroki/SKILL.md). Проверка: `node tools/validate-course.js m05`.

**Доработка движка T-SQL** (новая функция, синтаксис). Код — `js/engine/`. После правки прогоните обе проверки: они выполняют сотни запросов и быстро ловят регрессии. Добавьте пример в справочник (`content/cheatsheet.js`), если это новая возможность.

**Доработка интерфейса.** Код — `js/app/`, стили — `css/app.css`. Проверьте вручную: светлая и тёмная тема, две-три палитры (кнопка с палитрой вверху), узкое окно, режимы «в браузере» и «в папке», `file://` и `http://`. Цвета берите из переменных (`var(--primary)`, `var(--grad)`, `var(--surface)`…), а не пишите числами — иначе элемент не перекрасится при смене палитры. Подробности — скилл [sql-kurs-razrabotka](../skills/sql-kurs-razrabotka/SKILL.md).

**Новая палитра.** В `css/app.css` (раздел «Палитры») скопируйте пару блоков любой палитры, дайте новое имя в `data-palette` и поменяйте значения; добавьте строку `{ id, name, hint }` в `App.PALETTES` (`js/app/app.js`). Проверьте обе темы: ссылки и текст основного цвета читаются на карточке, белый текст — на обоих концах градиента кнопки.

**Подсказки и экскурсии.** Тексты — в `content/guide.js`, там же описан формат. Добавили на страницу кнопку или блок — дайте кнопке-значку понятный `title` (из него делается всплывающая подпись), а важному элементу — метку `'data-guide': 'имя'` и шаг в экскурсии этой страницы. Новая страница — новая экскурсия с полем `page`. Шаг для элемента, который есть не всегда, писать можно: если элемента нет, шаг пропускается. После правки — `node tools/validate-guide.js` и `python3 tools/ui-smoke.py`.

## Правила проекта

- **Никаких внешних зависимостей и сети.** Курс должен работать из папки без интернета. Не подключайте CDN, шрифты, библиотеки.
- **Только чтение данных.** Движок не выполняет `INSERT`/`UPDATE`/`DELETE`/DDL — это курс по SELECT.
- **id не меняются.** id модулей, уроков, задач и баз — ключи прогресса учеников. Новое — с новыми id, старое не переименовывается.
- **Интерфейс и тексты — на русском**, понятным языком для аналитика, который пришёл из Excel.
- **Ученик не должен терять прогресс.** Любые изменения в `storage.js` — с проверкой восстановления, двух вкладок и закрытия вкладки.
- **Интерфейс объясняет себя сам.** У каждой кнопки-значка — `title`; у важных элементов страницы — шаг экскурсии (см. выше).
- После правки баз — `node tools/build-index.js`, иначе на сайте и в режиме «в браузере» будет старая версия.

## Публикация на GitHub Pages

Workflow [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) при каждом push в `main`:

1. проверяет основной курс и все базы — при ошибке сайт не обновляется;
2. пересобирает `schemas/index.js` и, если он изменился, сохраняет его в репозиторий;
3. публикует сайт на GitHub Pages.

Для pull request выполняются только проверки.

Однократная настройка: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Адрес сайта: `https://<владелец>.github.io/<репозиторий>/`.

## Офлайн-архив для учеников

Архив — это просто содержимое репозитория: *Code → Download ZIP* на GitHub. Папки `tools/`, `skills/`, `docs/`, `.github/` ученикам не мешают; при желании их можно удалить из архива.

## Pull request

1. Сделайте форк и ветку.
2. Внесите изменения, запустите `npm run check` (или команды проверки по отдельности).
3. Опишите в PR, что изменилось и как вы это проверили.
