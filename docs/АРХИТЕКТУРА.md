# Архитектура приложения

Курс — одностраничное приложение на чистом JavaScript (ES5-стиль, `var`/функции, местами `async/await`). Без фреймворков, без сборки, без внешних библиотек и без сети: всё лежит в репозитории и работает и с `file://`, и с сайта.

## Загрузка

`index.html` подключает файлы по порядку:

1. **Движок** `js/engine/*.js` и настройки `content/course.js` — обычными `<script>`.
2. Небольшой загрузчик по одному подключает: модули `content/modules/*` (в порядке `COURSE.moduleFiles`), `content/trainer.js`, `content/cheatsheet.js`, `content/guide.js`, **необязательный** `schemas/index.js` и файлы приложения `js/app/*`. Если обязательный файл не загрузился, показывается ошибка со списком файлов.
3. `App.start()`.

Почему скрипты, а не `fetch`: с `file://` браузер не даёт читать JSON через `fetch`, а `<script>` работает всегда. По той же причине все учебные базы собираются в `schemas/index.js` (см. ниже).

Все модули пишут в глобальные объекты: `TSQL`, `PackFormat`, `COURSE`, `CHEAT`, `U`, `Store`, `Packs`, `Editor`, `Grid`, `Checker`, `Widgets`, `SchemaPanel`, `App`.

## Учебный движок T-SQL — `js/engine/`

| Файл | Что внутри |
|---|---|
| `tsql-core.js` | типы данных (`T.TY`), преобразования и `CAST`/`CONVERT`, сравнение строк без учёта регистра (порядок как в SQL Server: знаки, цифры, латиница, затем кириллица), даты, ошибки в стиле SSMS (`T.SqlError`, номера 102, 207, 208, 8120…), токенизатор |
| `tsql-parser.js` | синтаксический анализ в дерево: `SELECT` со всеми частями, `JOIN`/`APPLY`, подзапросы, `UNION`/`INTERSECT`/`EXCEPT`, `WITH` (в т. ч. рекурсивные CTE), `PIVOT`-подсказка, `DECLARE`/`SET` переменных, `#временные` таблицы, `USE`. Изменяющие команды (`INSERT`, `UPDATE`, `DELETE`, `CREATE`…) запрещены с понятным сообщением |
| `tsql-funcs.js` | встроенные функции: строковые, числовые, даты (`DATEADD`, `DATEDIFF`, `EOMONTH`, `FORMAT`…), `ISNULL`/`COALESCE`/`IIF`, `DB_NAME()` и др. |
| `tsql-exec.js` | выполнение: области видимости, агрегаты, `GROUP BY` с `ROLLUP`/`CUBE`/`GROUPING SETS`, оконные функции, сортировка, `TOP … WITH TIES`, `OFFSET/FETCH`, несколько баз в сеансе, пошаговая трассировка, подсказки к ошибкам (`T.explain`) |
| `bankdb.js` | встроенная база «Учебный банк» (`T.buildBankDb()`), генерируется детерминированно |
| `packs.js` | формат учебных баз (`PackFormat`): разбор `schema.json`, CSV, разметки текстов, сборка таблиц, проверка заданий, сборка `schemas/index.js` |

Главный вход:

```js
var r = TSQL.execute(sql, db, { dbs: { bank: bankDb, shop: shopDb }, now: someDate, trace: true });
// r.results  — [{ columns: [...], types: [...], rows: [[...], ...] }, ...]  по одному на каждый SELECT
// r.messages — ['(затронуто строк: 5)', ...]
// r.error    — null или { number, message, line }
// r.trace    — шаги выполнения для вкладки «Пошагово» (FROM → WHERE → GROUP BY → …)
// r.useDb    — имя базы после USE
```

База в памяти — объект `{ name, tables: { lower_name: { name, columns: [{ name, type, desc }], rows: [[...]] } } }`. Даты хранятся числами (мс), десятичные — с учётом точности и масштаба.

## Учебные базы — `schemas/` и `js/app/registry.js`

Каждая база — папка (`schema.json`, `data/*.csv`, задания, уроки) в формате [schemas/ФОРМАТ.md](../schemas/ФОРМАТ.md). `Packs.load()` собирает список:

1. встроенный банк;
2. базы **из подключённой папки** (если курс открыт из своей папки и она подключена) — иначе базы **из `schemas/index.js`**;
3. базы, добавленные в этом браузере кнопкой «Добавить базу» (хранятся в IndexedDB; без папки они важнее копий из `index.js`).

`schemas/index.js` — это `window.SQLKURS_BUNDLE = { sig, built, packs: [{ name, kind, files }] }`, где `files` — тексты всех файлов базы. Его собирает `node tools/build-index.js` (и GitHub Actions при каждом push), а в офлайн-режиме — сам курс, если папка подключена с записью. На сайте (`Store.hosted`) выбранная папка не считается папкой курса: базы сайта подключаются всегда, а `index.js` в неё не пишется.

`Packs.load()` можно вызывать сколько угодно раз: вызовы выполняются по очереди, новый список собирается отдельно и подменяет прежний целиком, поэтому страницы не видят «полупустой» список.

`PackFormat.normalize()` превращает файлы в объект базы: таблицы, связи, задания с пространством имён `id:локальный_id`, уроки, примеры. Таблицы строятся лениво (`PackFormat.getDb`) при первом обращении.

## Проверка заданий — `js/app/checker.js`

`Checker.check(task, sql, db, opts)` выполняет эталон и запрос ученика и сравнивает **результаты**:

1. ошибка выполнения → понятное сообщение с подсказкой;
2. число и типы столбцов, имена (если `check.names`);
3. строки как мультимножества: лишние / недостающие строки с примерами;
4. порядок (`check.order` — по ключам, `check.ordered` — строго);
5. `check.require` / `check.forbid` — регулярные выражения по коду без комментариев и строк.

Тот же модуль использует инструменты проверки (`tools/validate-*.js`): эталон должен проходить сам себя, варианты `wrong` — не проходить, `alsoOk` — проходить.

## Хранилище — `js/app/storage.js`

Режимы (`Store.mode`):

| Режим | Где прогресс | Когда |
|---|---|---|
| `fs` | `progress/<логин>.json` в выбранной папке (File System Access API) | Chrome/Edge, папка подключена с записью |
| `local` | браузер: `localStorage` + копия в IndexedDB `sqlkurs-vault` | «Хранить в браузере», «только для чтения», Firefox/Safari |

Надёжность режима «в браузере»:

- каждое сохранение пишется сразу в `localStorage` (синхронно) и в IndexedDB; при чтении берётся более свежая копия по `rev`/`updated`, пропавшая восстанавливается;
- снимки в IndexedDB (`snaps`): не реже раза в 15 минут занятий, 30 последних, всегда перед сбросом прогресса и перед загрузкой прогресса из файла;
- запись через 200 мс после изменения, при скрытии вкладки и синхронно при `pagehide`/`beforeunload`;
- одна вкладка на пользователя: ключ `sqlkurs.active.<логин>` и событие `storage` — вторая вкладка ставит первую на паузу;
- метки `sqlkurs.firstSeen` / `lastOpen` — «Проверка браузера» показывает, сохраняются ли данные между запусками;
- `navigator.storage.persist()` — просьба не удалять данные при нехватке места.

Записи одного пользователя идут строго по очереди (`Store.saveNow` ставит их в цепочку и сразу запоминает, куда писать): две одновременные записи файла не могут завершиться в обратном порядке, а запись, начатая при выходе, доходит до файла, даже когда страница входа уже переподключает хранилище. Возврат на `#/start` (в том числе кнопкой «Назад») — это выход из учётной записи.

Ручки (handle) папок и выбор режима запоминаются в IndexedDB `sqlkurs-store` и `localStorage`.

## Таблицы — `js/app/datagrid.js`

Все таблицы курса — результаты запросов, просмотр данных, пошаговый режим, виджеты, сводка по группе и даже таблицы из текста уроков — рисует один компонент `DataGrid`. Новый вид таблицы не пишется заново, а наследуется:

```js
var My = DataGrid.extend({
  defaults: { rowNumbers: false, status: true },                 // свои значения по умолчанию
  formatCell: function (td, value, rowIndex, colIndex) { … }     // свой вывод ячейки
});
view.appendChild(new My({ columns: ['Имя', 'Сумма'], rows: [['Айбек', '10']], kinds: ['str', 'int'] }).el);
```

| Вид | Где используется |
|---|---|
| `DataGrid` | базовый: всё включено |
| `DataGrid.Result` | результат запроса — строка состояния видна всегда |
| `DataGrid.Mini` | задания, виджеты, пошаговый режим, просмотр таблицы (`Grid.table(...)` создаёт его) |
| `DataGrid.Prose` | таблицы из текста урока: `DataGrid.fromTable(tableEl)` — ячейки с разметкой, перенос строк |

Что умеет: меню столбца (сортировка, фильтр по значениям с поиском и по условию, «левее / правее»), выделение диапазона мышью и с клавиатуры (Shift + стрелки, Ctrl+A), итоги по выделенному (число ячеек, сумма, среднее), копирование с табуляцией для Excel (Ctrl+C, с заголовками — Ctrl+Shift+C), перенос столбцов перетаскиванием заголовка, ширина за правый край заголовка. Строки рисуются порциями (`pageSize`), остальные — при прокрутке. Параметры: `columns`, `rows`, `kinds`, `types`, `raw` (исходные значения для сортировки чисел), `rowClass(i)`, `html`, `wrap`, `rowNumbers`, `status`, а также выключатели `filter`, `sort`, `select`, `reorder`, `resize`. Доступ к компоненту из разметки — `element.dataGrid`.

## Схема связей — `js/app/erd.js`

`App.erd(pack)` возвращает `{ el, draw(), view }`. Таблицы и связи рисуются на `<canvas>` (с учётом плотности экрана и темы), всё остальное — обычная разметка: панель масштаба, подсказка, легенда. Расположение подбирается под размер области: сетка автора базы (`layout` в `schema.json`) остаётся, если схема при ней читается, иначе таблицы раскладываются в столько колонок, сколько помещается. Сдвинутые пользователем таблицы запоминаются в `localStorage` (`sqlkurs.erd.<id базы>`). Вид связи определяется по данным: значения ссылки не повторяются — «один к одному», в ссылке есть `NULL` — «необязательная» (пунктир), ссылка на свою таблицу — «иерархия». Цвета типов и связей — переменные `--cat-*` и `--rel-*` в `css/app.css` (те же цвета у типов в панели «Схема базы»).

Чёткость схемы. Холст совпадает с экраном «пиксель в пиксель»: его размер берётся у самого холста (не у области с рамкой) и в пикселях экрана — из `ResizeObserver` (`devicePixelContentBoxSize`), потому что при масштабе системы 125 % или масштабе страницы 110 % размер дробный и округлить его «как на экране» может только браузер. Рисунок ставится на сетку экрана: сдвиг схемы — целое число пикселей, каждая таблица начинается с целого пикселя, её линии, рамка и строки текста — тоже (`paintNode`: `qx`, `qy`, `line`). Холст непрозрачный (`alpha: false`), поле закрашивается цветом палитры — так текст сглаживается как обычный текст страницы. Если что-то из этого нарушить, схема становится мутной; проверка — `tools/ui-smoke.py` (размер холста равен размеру на экране).

## Подсказки и обучение — `js/app/guide.js` и `content/guide.js`

Тексты отделены от механики: в `content/guide.js` (`window.GUIDE`) — экскурсии и содержимое страницы «О курсе», в `js/app/guide.js` — движок.

- **Экскурсия** — список шагов. Шаг привязан к элементу страницы меткой `data-guide="имя"` (метки расставлены там, где элементы создаются) либо селектором CSS, если в `at` он начинается с `.`, `#` или `[`. Движок затемняет страницу, оставляя «окно» вокруг элемента, и ставит пояснение рядом: снизу, сверху или сбоку — где помещается; на телефоне — во всю ширину. Шаг, чей элемент не найден (или не подходит по `only: 'desktop' | 'mobile'`), пропускается. Управление: кнопки, `←` `→`, `Esc`.
- **Своя экскурсия у страницы** — поле `page` (регулярное выражение адреса). Её запускает кнопка «?» (`Guide.menu()`): «Экскурсия по этой странице», «Подсказки на странице» (`Guide.marks(id)` — номера на всех элементах сразу, нажатие открывает пояснение), «Как работать с таблицей» (если на странице есть таблица результата), «О курсе». На компьютере «?» — в верхней панели, на телефоне — внизу меню.
- **Первое знакомство** — `Guide.offer(page)` на главной: предложение короткой экскурсии; после ответа больше не показывается. Точка на кнопке «?» отмечает страницу, экскурсию которой ещё не открывали.
- **Страница «О курсе»** (`#/help`, пункт меню «Помощь»): описание, разделы с кнопками «Экскурсия» (`Guide.go(id)` открывает нужную страницу и запускает экскурсию; для урока, задачи и таблицы адрес подбирается по курсу), очки и ранги (числа берутся из `COURSE.config` и `App.RANKS`), горячие клавиши, частые вопросы. На странице входа то же описание — в окне (`Guide.about()`).
- **Всплывающие подписи** — вместо системных: текст берётся из атрибута `title` (при первом наведении он переезжает в `data-tip`), подпись появляется при наведении, при переходе с клавиатуры и по долгому нажатию на сенсорном экране. Поэтому у каждой кнопки-значка должен быть `title`.
- **Состояние** — в прогрессе ученика: `settings.guide = { seen, peek, offered, off }` (`seen` — экскурсию запускали, `peek` — меню «?» на этой странице открывали, `off` — «не предлагать экскурсии», переключается в профиле).

Проверки: `node tools/validate-guide.js` (структура, метки есть в коде, значки и адреса существуют) и `tools/ui-smoke.py` (на компьютере и телефоне каждый шаг каждой экскурсии находит свой элемент, пояснение не выходит за экран).

## Прогресс пользователя

Объект пользователя (`App.user`) — один JSON: `id`, `name`, `dept`, `pinHash`, `xp`, `items` (решённые задачи и ответы по id), `lessons`, `modulesDone`, `ach`, `stats`, `streak`, `settings` (тема, выбранные базы, панель схемы, автокопия), `sandbox`, `backup`, `rev`, `updated`. Поэтому **id заданий нельзя менять** — по ним хранится прогресс.

## Оформление — `css/app.css`

Минималистичный стиль с «парящими островками»: панели и карточки — полупрозрачные, с эффектом матового стекла (`backdrop-filter`), над мягкими цветными пятнами фона (`#bg`). Переменные цветов (`--primary`, `--surface`, `--glass`, `--border`, `--muted`…) для светлой и тёмной темы. Без внешних шрифтов.

**Палитры.** Восемь цветовых сочетаний («Океан» — по умолчанию, «Небо и солнце», «Аквамарин», «Изумруд», «Лес и песок», «Янтарь», «Полночь и золото», «Графит»), каждое — для светлой и тёмной темы. Палитру задаёт атрибут `data-palette` у `<html>`, тему — `data-theme`. В `css/app.css` у каждой палитры пара блоков: `[data-palette="id"]` (светлая) и `[data-theme="dark"][data-palette="id"], [data-theme="dark"] [data-palette="id"]` (тёмная). В них — основной цвет и градиент кнопок (`--primary`, `--grad`, `--accent`, `--accent-2`, `--glow`), цвет фона и «стёкол», пятна фона (`--blob1..3`) и цвета живого фона (`--bg-hues`, `--bg-sat`, `--bg-glow`, `--bg-dot`). Цвета типов столбцов и связей на схеме, подсветка кода, цвета «верно/ошибка» — общие для всех палитр. Тот же атрибут `data-palette` на любом элементе красит только его — так сделаны образцы в окне выбора.

Список палитр — `App.PALETTES` (`js/app/app.js`); `App.palette()` — текущая, `App.setPalette(id)` и `App.setTheme('light' | 'dark')` — смена, `App.palettePicker()` и `App.themeSwitch()` — элементы выбора (страница профиля), `App.showAppearance()` — окно «Оформление» (кнопка с палитрой в верхней панели, на телефоне — в меню, до входа — в углу страницы). Выбор хранится у ученика (`settings.palette`, `settings.theme`) и в памяти браузера (`sqlkurs.palette`, `sqlkurs.theme`) — по ней короткий сценарий в `<head>` ставит атрибуты до отрисовки страницы. `App.applyTheme()` применяет всё разом и перекрашивает значок вкладки и цвет панели браузера; живой фон (`bg.js`) и схема на холсте (`erd.js`) следят за обоими атрибутами и перекрашиваются сами.

Фон — слой `#bg` под содержимым (`z-index: -1`; цвет фона задан у `html`, а не у `body`, иначе он закрыл бы этот слой). Его оживляет `js/app/bg.js`: цветные облака и «созвездие» из точек на canvas плывут сами, сдвигаются при прокрутке с разной глубиной и тянутся к курсору. Анимация идёт не чаще ~40 кадров в секунду, останавливается в скрытой вкладке, сама упрощается на слабом компьютере, не включается при системной настройке «меньше движения» и выключается в профиле (`settings.bgAnim`). Без неё видны статичные пятна (`#bg i`).

Кнопка ↔ в верхней панели (и настройка в профиле) растягивает страницы на всю ширину экрана: класс `wide-ui` у `body`, настройка `settings.wide`.

Оболочка (`index.html`: `#side`, `#topbar`, `#view`, `#tabbar`):

| Экран | Навигация |
|---|---|
| компьютер (≥ 1024 px) | левая панель (сворачивается до значков кнопкой или «гамбургером», выбор запоминается) + верхняя панель |
| телефон и планшет (< 1024 px) | верхняя панель с «гамбургером» (выдвижное меню, закрывается жестом влево) + нижняя панель из пяти разделов; при прокрутке вниз обе панели прячутся, при вводе текста нижняя скрывается |

На телефоне окна (`U.modal`) открываются шторкой снизу, схема базы в задачах — тоже шторкой (`A.schemaSheet`), длинные пояснения спрятаны под «Подробнее» (`U.more`) или кнопку «i» (`U.info`).
