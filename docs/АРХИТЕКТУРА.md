# Архитектура приложения

Курс — одностраничное приложение на чистом JavaScript (ES5-стиль, `var`/функции, местами `async/await`). Без фреймворков, без сборки, без внешних библиотек и без сети: всё лежит в репозитории и работает и с `file://`, и с сайта.

## Загрузка

`index.html` подключает файлы по порядку:

1. **Движок** `js/engine/*.js` и настройки `content/course.js` — обычными `<script>`.
2. Небольшой загрузчик по одному подключает: модули `content/modules/*` (в порядке `COURSE.moduleFiles`), `content/trainer.js`, `content/cheatsheet.js`, **необязательный** `schemas/index.js` и файлы приложения `js/app/*`. Если обязательный файл не загрузился, показывается ошибка со списком файлов.
3. `App.start()`.

Почему скрипты, а не `fetch`: с `file://` браузер не даёт читать JSON через `fetch`, а `<script>` работает всегда. По той же причине все учебные базы собираются в `schemas/index.js` (см. ниже).

Все модули пишут в глобальные объекты: `TSQL`, `PackFormat`, `COURSE`, `CHEAT`, `U`, `Store`, `Packs`, `Editor`, `Grid`, `Checker`, `Widgets`, `SchemaPanel`, `App`.

## Учебный движок T-SQL — `js/engine/`

| Файл | Что внутри |
|---|---|
| `tsql-core.js` | типы данных (`T.TY`), преобразования и `CAST`/`CONVERT`, сравнение строк без учёта регистра, даты, ошибки в стиле SSMS (`T.SqlError`, номера 102, 207, 208, 8120…), токенизатор |
| `tsql-parser.js` | синтаксический анализ в дерево: `SELECT` со всеми частями, `JOIN`/`APPLY`, подзапросы, `UNION`/`INTERSECT`/`EXCEPT`, `WITH` (в т. ч. рекурсивные CTE), `PIVOT`-подсказка, `DECLARE`/`SET` переменных, `#временные` таблицы, `USE`. Изменяющие команды (`INSERT`, `UPDATE`, `DELETE`, `CREATE`…) запрещены с понятным сообщением |
| `tsql-funcs.js` | встроенные функции: строковые, числовые, даты (`DATEADD`, `DATEDIFF`, `EOMONTH`, `FORMAT`…), `ISNULL`/`COALESCE`/`IIF`, `DB_NAME()` и др. |
| `tsql-exec.js` | выполнение: области видимости, агрегаты, `GROUP BY` с `ROLLUP`/`CUBE`/`GROUPING SETS`, оконные функции, сортировка, `TOP … WITH TIES`, `OFFSET/FETCH`, несколько баз в сеансе, пошаговая трассировка, подсказки к ошибкам (`T.explain`) |
| `bankdb.js` | встроенная база «Учебный банк» (`T.buildBankDb()`), генерируется детерминированно |
| `packs.js` | формат учебных баз (`PackFormat`): разбор `schema.json`, CSV, разметки текстов, сборка таблиц, проверка заданий, сборка `schemas/index.js` |

Главный вход:

```js
var r = TSQL.execute(sql, db, { dbs: { bank: bankDb, shop: shopDb }, now: someDate, trace: true });
// r.results  — [{ columns: [...], types: [...], rows: [[...], ...] }, ...]  по одному на каждый SELECT
// r.messages — ['(затронуто строк: 5)', ...]
// r.error    — null или { number, message, line }
// r.trace    — шаги выполнения для вкладки «Пошагово» (FROM → WHERE → GROUP BY → …)
// r.useDb    — имя базы после USE
```

База в памяти — объект `{ name, tables: { lower_name: { name, columns: [{ name, type, desc }], rows: [[...]] } } }`. Даты хранятся числами (мс), десятичные — с учётом точности и масштаба.

## Учебные базы — `schemas/` и `js/app/registry.js`

Каждая база — папка (`schema.json`, `data/*.csv`, задания, уроки) в формате [schemas/ФОРМАТ.md](../schemas/ФОРМАТ.md). `Packs.load()` собирает список:

1. встроенный банк;
2. базы **из подключённой папки** (если курс открыт из своей папки и она подключена) — иначе базы **из `schemas/index.js`**;
3. базы, добавленные в этом браузере кнопкой «Добавить базу» (хранятся в IndexedDB; без папки они важнее копий из `index.js`).

`schemas/index.js` — это `window.SQLKURS_BUNDLE = { sig, built, packs: [{ name, kind, files }] }`, где `files` — тексты всех файлов базы. Его собирает `node tools/build-index.js` (и GitHub Actions при каждом push), а в офлайн-режиме — сам курс, если папка подключена с записью. На сайте (`Store.hosted`) выбранная папка не считается папкой курса: базы сайта подключаются всегда, а `index.js` в неё не пишется.

`PackFormat.normalize()` превращает файлы в объект базы: таблицы, связи, задания с пространством имён `id:локальный_id`, уроки, примеры. Таблицы строятся лениво (`PackFormat.getDb`) при первом обращении.

## Проверка заданий — `js/app/checker.js`

`Checker.check(task, sql, db, opts)` выполняет эталон и запрос ученика и сравнивает **результаты**:

1. ошибка выполнения → понятное сообщение с подсказкой;
2. число и типы столбцов, имена (если `check.names`);
3. строки как мультимножества: лишние / недостающие строки с примерами;
4. порядок (`check.order` — по ключам, `check.ordered` — строго);
5. `check.require` / `check.forbid` — регулярные выражения по коду без комментариев и строк.

Тот же модуль использует инструменты проверки (`tools/validate-*.js`): эталон должен проходить сам себя, варианты `wrong` — не проходить, `alsoOk` — проходить.

## Хранилище — `js/app/storage.js`

Режимы (`Store.mode`):

| Режим | Где прогресс | Когда |
|---|---|---|
| `fs` | `progress/<логин>.json` в выбранной папке (File System Access API) | Chrome/Edge, папка подключена с записью |
| `local` | браузер: `localStorage` + копия в IndexedDB `sqlkurs-vault` | «Хранить в браузере», «только для чтения», Firefox/Safari |

Надёжность режима «в браузере»:

- каждое сохранение пишется сразу в `localStorage` (синхронно) и в IndexedDB; при чтении берётся более свежая копия по `rev`/`updated`, пропавшая восстанавливается;
- снимки в IndexedDB (`snaps`): не реже раза в 15 минут занятий, 30 последних, всегда перед сбросом прогресса;
- запись через 200 мс после изменения, при скрытии вкладки и синхронно при `pagehide`/`beforeunload`;
- одна вкладка на пользователя: ключ `sqlkurs.active.<логин>` и событие `storage` — вторая вкладка ставит первую на паузу;
- метки `sqlkurs.firstSeen` / `lastOpen` — «Проверка браузера» показывает, сохраняются ли данные между запусками;
- `navigator.storage.persist()` — просьба не удалять данные при нехватке места.

Ручки (handle) папок и выбор режима запоминаются в IndexedDB `sqlkurs-store` и `localStorage`.

## Приложение — `js/app/`

| Файл | Что внутри |
|---|---|
| `util.js` | `U.h()` — создание DOM (`h("div.cls", {attrs}, ...дети)`), модальные окна, всплывающие сообщения, даты, скачивание файлов |
| `app.js` | маршрутизатор по `location.hash`, стартовая страница (место хранения, вход, восстановление), главная, профиль, достижения, сводка по группе, XP и ранги, «Проверка браузера», копии прогресса |
| `pages.js` | модули, уроки по шагам, задачи, ДЗ, тренажёр, практикум баз, песочница, схема, справочник |
| `packpages.js` | страница «Базы»: выбор баз, проверка заданий, добавление базы из папки/файла, скачивание `index.js` |
| `editor.js` | редактор SQL: подсветка, номера строк, F5/Ctrl+Enter, выполнение выделенного, автодополнение таблиц/столбцов/псевдонимов |
| `grid.js` | вывод результатов, сообщений и ошибок, вкладка «Пошагово» |
| `schemapanel.js` | панель «Схема базы» рядом с редактором, просмотр данных, схема связей (ERD) |
| `widgets.js` | интерактивные схемы уроков (JOIN, NULL, LIKE, окна, GROUP BY…) — считают результат настоящим движком |
| `checker.js` | проверка заданий (см. выше) |

Маршруты: `#/start`, `#/home`, `#/m/<модуль>`, `#/l/<модуль>/<урок>`, `#/hw/<модуль>`, `#/t/<задача>`, `#/trainer[/уровень][/база]`, `#/set/<набор>`, `#/sandbox[/база]`, `#/schema[/база]`, `#/packs`, `#/cheat`, `#/profile`, `#/ach`, `#/team`.

## Прогресс пользователя

Объект пользователя (`App.user`) — один JSON: `id`, `name`, `dept`, `pinHash`, `xp`, `items` (решённые задачи и ответы по id), `lessons`, `modulesDone`, `ach`, `stats`, `streak`, `settings` (тема, выбранные базы, панель схемы, автокопия), `sandbox`, `backup`, `rev`, `updated`. Поэтому **id заданий нельзя менять** — по ним хранится прогресс.

## Оформление — `css/app.css`

Переменные цветов (`--primary`, `--surface`, `--border`, `--muted`…) для светлой и тёмной темы, адаптивная вёрстка (узкие экраны ≤ 980 px). Без внешних шрифтов.
