# Учебная база для курса «SELECT с нуля»

Курс — HTML-приложение без сервера (репозиторий https://github.com/kutya001/SQL-Study, сайт https://kutya001.github.io/SQL-Study/). Учебные базы лежат в `schemas/ИМЯ/` и подключаются без правки кода. Результат работы — папка базы (в репозитории или архивом), прошедшая проверку без ошибок.

## 0. Подготовка
- Получи код курса: `git clone https://github.com/kutya001/SQL-Study` (или архив `Code → Download ZIP`, или папку `SELECT_kurs`, которую приложил пользователь). Дальше `КУРС` — корень этой папки.
- Прочитай `КУРС/schemas/ФОРМАТ.md` целиком — это спецификация формата. Образцы: `schemas/shop/`, `schemas/sewing/`, `schemas/cargo/` (полные базы) и `schemas/_шаблон/` (минимальная). Генераторы данных образцов — `tools/generators/gen_*.js`: возьми один за основу.
- Нужен Node.js 18+. Инструменты — в `КУРС/tools/` (зависимостей нет).
- Уточни у пользователя только тематику, если её нет. Остальное (число таблиц, объём) — по умолчанию из п. 1.

## 1. Проектирование
- 6–8 таблиц, латинские имена в PascalCase, у каждой `pk`, связи через `fk`. Обязательно одна «справочная» иерархия (ParentID или ManagerID) для self-join и рекурсии.
- Реализм для Кыргызстана и СНГ: сомы, города (Бишкек, Ош, Каракол, Токмок, Джалал-Абад, Нарын, Талас), кыргызские и русские имена, телефоны `+996XXXXXXXXX`.
- Период данных 2025-01-01 … 2026-10-31, поле `"today": "2026-10-31"` в schema.json (это значение вернёт `GETDATE()`). Самая большая таблица 3–10 тыс. строк.
- Специально заложи «ловушки» для заданий: NULL в необязательных полях; запись-справочник без пары (для LEFT JOIN / NOT EXISTS); статусы отмен/возвратов; дата-время (не только дата) в таблице операций; скидки/проценты; объект, открытый недавно.
- `id` базы — латиница (например `clinic`), `dbName` — PascalCase (`Clinic`). Не совпадать с уже существующими: `bank`/`Bank`, `shop`/`Shop`, `sewing`/`Sewing`, `cargo`/`Cargo` (посмотри список папок в `schemas/`).
- Опиши в `description` бизнес-правила расчёта (что считать выручкой и т. п.) — задания на них ссылаются.

## 2. Данные
- Пиши генератор на Node с детерминированным ГСЧ (mulberry32 с фиксированным seed), чтобы данные можно было пересобрать. Сохрани его как `tools/generators/gen_ИМЯ.js` (по образцу соседних), а не внутри папки базы.
- Вывод: `schemas/ИМЯ/data/ИмяТаблицы.csv`, UTF-8, разделитель запятая, первая строка — имена столбцов, NULL — пустое поле, даты `ГГГГ-ММ-ДД`, дата-время `ГГГГ-ММ-ДД ЧЧ:ММ:СС`, десятичная точка.
- Соблюдай уникальность PK и ссылочную целостность FK (проверка это ловит).
- Связь со встроенным банком (база `Bank`) — по желанию: подключи движок (`require` файлов `js/engine/*.js`, см. начало `tools/lib.js`) и возьми клиентов из `TSQL.buildBankDb().tables.clients.rows` (столбцы: ClientID, LastName, FirstName, MiddleName, Gender, BirthDate (мс UTC), City, Phone, …).

## 3. Задания
Файлы `tasks.json` (4 набора по 6–8 задач: выборки → функции/NULL/даты → группировка/JOIN → CTE/окна), `trainer.json` (по 4 задачи на уровни 1–5), `examples.json` (~8 примеров, включая один запрос к двум базам и `USE`), `course.json` (1 модуль, 2 урока: text/example/quiz/task, мини-тренировка, 2 задачи ДЗ; можно шаг `widget` из списка в ФОРМАТ.md).

Перед тем как написать задачу, посмотри фактический результат эталона:

```bash
node tools/sql.js ИМЯ "SELECT TOP 10 ... ORDER BY ..."
```

Результат не пустой, без ничьих на границе TOP, числа разумные.

Правила честных задач:
- Проверяется результат, а не текст. Эталон должен быть однозначным: если `TOP` — есть `ORDER BY` с разбивкой ничьих и нет ничьих на границе; периоды по datetime — диапазоном `>= '20261001' AND < '20261101'`.
- Все суммы/доли — `CAST(... AS DECIMAL(p,s))`, тип указан в тексте. Деление — с `100.0`.
- Если в тексте сказано «назовите столбец» — `"check": {"names": true}`. Порядок важен — `order: [[номер_с_0, "desc"]]` (мягко) или `ordered: true` (строго).
- Для задач с несколькими разумными решениями добавляй `alsoOk`; для типичной ошибки — `wrong` (проверка убедится, что она не засчитывается).
- Тексты — простая разметка (`**жирный**`, `` `код` ``, списки, `> совет`), многострочное — массивом строк. SQL — тоже массивом строк.
- id задач уникальны и стабильны (`s1-1`, `tr3-2`, `q1`).

## 4. Проверка (обязательно)

```bash
node tools/check-pack.js schemas/ИМЯ      # одна база: данные, связи, все эталоны, wrong/alsoOk, вопросы
node tools/validate-packs.js              # все базы вместе (проверка конфликтов id и dbName)
```

Исправляй, пока не будет 0 ошибок; замечания разбери (0 строк у эталона, TOP без ORDER BY, лишние столбцы CSV).

Затем пересобери сборку баз — без неё база не появится на сайте и у тех, кто хранит прогресс в браузере:

```bash
node tools/build-index.js
```

## 5. Сдача
- **В репозиторий** (если есть доступ): ветка `baza-ИМЯ`, коммит с папкой `schemas/ИМЯ/`, генератором `tools/generators/gen_ИМЯ.js` и обновлённым `schemas/index.js`; pull request с описанием базы. После слияния GitHub Actions проверит всё и опубликует сайт.
- **Архивом**: упакуй папку базы в zip через Python `zipfile` (он ставит флаг UTF-8 для кириллических имён; `zip` из Info-ZIP — нет). В архиве — одна папка с именем, равным `id` (латиница, без `_` в начале). Пользователь распаковывает её в `schemas/` и на странице «Базы» нажимает «Обновить» (или «Добавить базу (папка)»), затем «Проверить задания» и отмечает «Изучаю».
- В ответе коротко: что за база (таблицы, объём, период), сколько задач по разделам, результат проверки, как подключить.
- Не меняй `id` базы и задач у уже выданной базы — к ним привязан прогресс учеников. При доработке существующей базы добавляй новые id, старые оставляй.
