# Разработка приложения «SELECT с нуля»

Курс — одностраничное приложение на чистом JavaScript без сборки, зависимостей и сервера. Работает из папки (`file://`) и с сайта (https://kutya001.github.io/SQL-Study/). Репозиторий: https://github.com/kutya001/SQL-Study.

## 0. Перед работой
- Получи код: `git clone https://github.com/kutya001/SQL-Study`. Дальше `КУРС` — корень.
- Прочитай `docs/АРХИТЕКТУРА.md` и `docs/РАЗРАБОТКА.md`. Для работы с контентом — `docs/КОНТЕНТ.md`, с учебными базами — `schemas/ФОРМАТ.md`.
- Найди нужное место кодом, а не догадкой: `grep -rn "…" js/ content/`. Главные точки входа: `TSQL.execute` (`js/engine/tsql-exec.js`), `Checker.check` (`js/app/checker.js`), `Store` (`js/app/storage.js`), `Packs.load` (`js/app/registry.js`), маршруты `A.route(...)` (`js/app/app.js`, `pages.js`, `packpages.js`).
- Запусти проверки до изменений, чтобы знать исходное состояние: `npm run check` (или команды из п. 3).

## 1. Правила проекта (не нарушать)
1. **Без внешних зависимостей и сети**: никаких CDN, npm-библиотек в браузере, внешних шрифтов, `fetch` к серверам. Новый файл подключай в `index.html` (движок — статическим `<script>`, приложение — в список загрузчика).
2. **Работает с `file://`**: не используй `fetch`/`import` для локальных файлов — только `<script>`. Модули пишут в глобальные объекты (`window.X = …`) в стиле соседнего кода: IIFE `(function (G) { 'use strict'; … })(window)`, `var`, функции; `async/await` допустим.
3. **Только чтение данных**: движок не выполняет изменяющие команды; новые возможности SQL — только для SELECT-сценариев. Сообщения об ошибках — в стиле SSMS (номер ошибки + понятный текст на русском) и подсказка в `T.explain`.
4. **id контента неизменны** (модули, уроки, задачи, базы): это ключи прогресса учеников.
5. **Прогресс не теряется**: изменения `storage.js` — только с проверкой записи в обе копии (localStorage + IndexedDB), восстановления, двух вкладок, закрытия вкладки и режима «в папке». Формат пользователя меняй совместимо (`migrate` в `app.js`).
6. **Режимы**: `file://` и `localhost` — курс в своей папке; любой другой адрес — сайт (`Store.hosted`). Не ломай ни один из них.
7. **Интерфейс — на русском**, простым языком для аналитика из Excel. Светлая и тёмная тема и восемь палитр (CSS-переменные в `css/app.css`, атрибуты `data-theme` и `data-palette` у `<html>`): цвета — только через переменные (`var(--primary)`, `var(--grad)`…), без фиолетовых и розовых оттенков. Узкие экраны.

## 2. Как делать изменения
- Маленькими шагами, читая окружающий код. Повторно используй существующие помощники (`U.h`, `U.modal`, `U.toast`, `Grid.renderRun`, `SchemaPanel.create`, `PackFormat.*`). Любая таблица — через общий компонент `DataGrid` (`js/app/datagrid.js`): `Grid.table(...)` или свой вид через `DataGrid.extend({...})`, а не новая разметка `<table>`.
- Новая функция T-SQL — в `js/engine/tsql-funcs.js` (по образцу соседних), ключевое слово — в токенизаторе/парсере, имя — в списках подсветки/автодополнения `js/app/editor.js`. Добавь пример в `content/cheatsheet.js`.
- Новый формат или поле учебной базы — в `js/engine/packs.js` (`normalize` + `validate`), описание — в `schemas/ФОРМАТ.md`.
- Новая страница — `A.route(/^#\/…\/([^/]+)$/, function (view, параметр1, …) { … })` (группы регулярного выражения приходят аргументами после `view`) и, если нужно, пункт меню в `app.js`.
- Тексты справки обновляй вместе с кодом: `ИНСТРУКЦИЯ.txt` (CRLF, UTF-8 с BOM — сохраняй как есть), `README.md`, `docs/*`.

## 3. Проверка (обязательно)

```bash
node tools/validate-course.js     # все примеры, эталоны, ДЗ, тренажёр и справочник основного курса
node tools/validate-packs.js      # все учебные базы
node tools/test-engine.js         # движок: запросы с известным результатом (при правке движка добавь сюда случай)
node tools/build-index.js         # если менялись schemas/ (сборка для сайта и режима «в браузере»)
node tools/sql.js bank "SELECT …" # быстрый запрос к базе
```

Для изменений интерфейса — ещё браузер:

```bash
pip install playwright && python -m playwright install chromium   # один раз
python3 tools/ui-smoke.py         # сайт (http) и папка (file://): вход, задача, базы, песочница, сохранение
```

и вручную: светлая/тёмная тема, две-три палитры (кнопка с палитрой вверху), узкое окно, «Хранить в браузере» и «В папке», консоль браузера без ошибок. Для изменений хранилища дополнительно: перезагрузка, закрытие вкладки сразу после действия, вторая вкладка, «Восстановить из файла», «Копии в браузере».

## 4. Публикация
- Ветка → коммит → pull request (на PR GitHub Actions выполнит проверки) → слияние в `main`.
- При push в `main` workflow `.github/workflows/pages.yml` проверяет курс и базы, пересобирает `schemas/index.js` и публикует сайт. Если проверки не прошли — сайт не обновится.
- Офлайн-версия для учеников — архив репозитория (`Code → Download ZIP`).

## 5. Отчёт
Коротко: что изменено и зачем, какие файлы, результат проверок (числа ошибок/предупреждений), что проверено в браузере и что пользователю стоит посмотреть самому.
