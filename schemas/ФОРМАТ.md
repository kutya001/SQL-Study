# Учебные базы курса «SELECT с нуля» — формат папки

Любую учебную базу можно добавить в курс **без правки кода**: положите её папку в `schemas/` рядом с `index.html` и нажмите «Обновить» на странице «Базы». Каждый ученик сам выбирает, какие базы изучать: одну или несколько сразу.

Образцы:
- `schemas/shop/` — полноценная база «Учебный маркет» (8 таблиц, ~10 тыс. строк, мини-курс, практикум, тренажёр, примеры);
- `schemas/_шаблон/` — минимальный шаблон «Библиотека». Папки с «_» в начале курс не загружает: скопируйте шаблон, переименуйте папку и правьте.

## 1. Состав папки

```
schemas/
  my-base/                ← имя папки любое (латиница, цифры, - и _)
    schema.json           ← ОБЯЗАТЕЛЬНО: описание базы и таблиц
    data/
      Orders.csv          ← данные: по файлу на таблицу, имя = имя таблицы
      Customers.csv
    tasks.json            ← практикум: наборы задач (необязательно)
    trainer.json          ← задачи тренажёра по уровням 1–5 (необязательно)
    examples.json         ← готовые запросы для песочницы (необязательно)
    course.json           ← модули с уроками (необязательно)
```

Можно всё положить в **один файл** `schemas/my-base.json`: это тот же `schema.json`, в котором есть ещё ключи `tasks`, `trainer`, `examples`, `course`, а данные таблиц записаны в `rows` (см. п. 3).

Все файлы — в кодировке **UTF-8**. JSON строгий: двойные кавычки, без запятой после последнего элемента, без комментариев.

### Файл `schemas/index.js` — все базы одним скриптом

Это не отдельная база, а **сборка** всех папок из `schemas/` в один файл. Браузер подключает его как обычный скрипт — без разрешения на папку, поэтому базы появляются и на компьютерах, где выбрать папку курса нельзя (режим «Хранить в браузере»).

- Вручную файл не правят. Его пересобирает:
  - команда `node tools/build-index.js` (в репозитории курса);
  - GitHub Actions — при каждом push, на сайте курса всегда свежая версия;
  - сам курс на любом ПК, где папка курса подключена **с записью** (при входе и по кнопке «Обновить» на странице «Базы»), если базы изменились;
  - вручную: страница «Базы» → «Добавить базу (папка)» → выбрать всю папку `schemas` → «⬇ Скачать index.js» → положить файл в `schemas/` вместо старого.
- Когда папка курса подключена, базы читаются из папок, а `index.js` не используется. На сайте курса базы всегда берутся из `index.js`.

## 2. schema.json

```json
{
  "id": "shop",
  "title": "Учебный маркет",
  "icon": "🛒",
  "dbName": "Shop",
  "version": "1.0",
  "author": "Имя автора",
  "order": 10,
  "default": false,
  "description": ["Текст о базе (строка или массив строк, см. п. 4)."],
  "tables": [
    {
      "name": "Orders", "title": "Чеки",
      "columns": [
        { "name": "OrderID", "type": "int", "pk": true, "desc": "Номер чека" },
        { "name": "CustomerID", "type": "int", "fk": "Customers.CustomerID", "desc": "Покупатель" },
        { "name": "OrderDate", "type": "datetime", "desc": "Дата и время" }
      ]
    }
  ],
  "relations": [["Orders.StoreID", "Stores.StoreID"]],
  "layout": { "Orders": [1, 2], "Customers": [0, 1] }
}
```

| Поле | Что это |
|---|---|
| `id` | Уникальный код базы: латиница, цифры, `-`, `_`. **Не меняйте после выдачи ученикам** — к нему привязан прогресс. |
| `title`, `icon` | Название и значок (эмодзи) в интерфейсе. |
| `dbName` | Имя базы в запросах: `USE Shop;`, `Shop.dbo.Orders`, `DB_NAME()`. Латиница без пробелов. По умолчанию — из `id`. |
| `description` | Описание на странице базы и на схеме. |
| `order` | Порядок в списке (меньше — выше; встроенный банк — 0). |
| `default` | `true` — база включена у всех, кто ещё не выбирал базы сам. |
| `today` | Необязательно: дата «сегодня» для этой базы (`"2026-10-31"`) — её вернёт `GETDATE()`. |
| `tables` | Таблицы. `name` — латиница без пробелов. `title` — описание. |
| `columns` | Столбцы: `name`, `type`, `desc`; `pk: true` — первичный ключ; `fk: "Таблица.Столбец"` — ссылка. Можно короче — массивом: `["OrderID", "int", "Номер чека"]`. |
| `relations` | Дополнительные связи, если не указаны через `fk`. |
| `layout` | Необязательно: положение таблиц на схеме `[колонка, строка]` с нуля. Без него таблицы расставляются по порядку. |

**Типы столбцов:** `int`, `bigint`, `smallint`, `tinyint`, `bit`, `decimal(p,s)` / `numeric(p,s)`, `money`, `float`, `real`, `varchar(n)`, `nvarchar(n)`, `char(n)`, `nchar(n)`, `varchar(max)`, `nvarchar(max)`, `date`, `datetime`, `datetime2`, `smalldatetime`, `uniqueidentifier`.

## 3. Данные

### CSV — `data/ИмяТаблицы.csv`
- Первая строка — **имена столбцов** (как в schema.json; порядок может быть любым).
- Разделитель — запятая, точка с запятой или табуляция (определяется по первой строке). Файл, сохранённый из Excel как «CSV UTF-8», подходит.
- Пустое поле или `NULL` → NULL. Пустая строка `''` → `""` (две кавычки).
- Текст с разделителем, кавычкой или переводом строки — в двойных кавычках, кавычка внутри удваивается: `"Хлеб ""Бородинский"""`.
- Числа: `1234.50` (допускается и `1234,50`, если разделитель полей — `;`).
- Даты: `2026-10-31`, дата-время: `2026-10-31 14:05:00`. Допускаются `20261031` и `31.10.2026`.
- `bit`: `1`/`0`, `true`/`false`.
- Другое имя файла можно указать в таблице: `"file": "data/orders_2026.csv"`.

### Данные прямо в JSON
```json
{ "name": "Authors", "columns": [...], "rows": [[1, "Айтматов", "1928-12-12"], [2, "Толстой", null]] }
```
Строки — массивы значений в порядке столбцов (или объекты `{"AuthorID": 1, ...}`).

При загрузке курс проверяет типы, уникальность первичного ключа и ссылки внешних ключей — ошибки видны на странице «Базы».

## 4. Тексты заданий и уроков

Любой текст (`description`, `text`, `hint`, `explain`, `q`, `desc`, `goal`) можно писать **строкой** или **массивом строк** — так удобнее многострочный текст. SQL (`solution`, `sql`) — тоже строкой или массивом строк.

Простая разметка:
- `**жирный**`, `*курсив*`, `` `код` ``, `[ссылка](https://...)`;
- строки с `- ` или `1. ` — список;
- строка с `> ` — блок-совет, с `! ` — блок «важно»;
- `### Заголовок`;
- блок SQL с подсветкой — между строками ` ```sql ` и ` ``` `;
- пустая строка — новый абзац.

Если текст начинается с `<`, он считается готовым HTML.

## 5. Задание (общий формат)

```json
{
  "id": "s1-2",
  "title": "Романы по цене",
  "text": "Выведите название и цену романов, от дорогих к дешёвым.",
  "solution": "SELECT Title, Price FROM Books WHERE Genre = N'Роман' ORDER BY Price DESC;",
  "hint": "Сортировка по убыванию — ORDER BY … DESC.",
  "explain": "Пояснение, которое видно после решения (необязательно).",
  "starter": "SELECT ... -- заготовка в редакторе (необязательно)",
  "check": { "order": [[1, "desc"]] },
  "alsoOk": ["другое верное решение — курс проверит, что оно засчитывается"],
  "wrong": ["типичное неверное решение — курс проверит, что оно НЕ засчитывается"],
  "allowEmpty": false
}
```

Курс сравнивает **результат** запроса ученика с результатом эталона (`solution`), поэтому засчитывается любое верное решение. Числа сравниваются по значению, строки — точно (лишние пробелы считаются ошибкой, но ученик увидит подсказку).

`check` — дополнительные требования:
| Ключ | Значение |
|---|---|
| `names: true` | Имена столбцов должны совпасть с эталоном (без учёта регистра). Используйте, когда в тексте сказано «назовите столбец …». |
| `ordered: true` | Строки — строго в том же порядке, что у эталона. Нужен однозначный ORDER BY (с «разбивкой ничьих»). |
| `order: [[1, "desc"], [0, "asc"]]` | Проверить только сортировку по указанным столбцам (номера с **0**). Мягче, чем `ordered`. |
| `require: [["регулярное выражение", "сообщение"]]` | Обязательная конструкция, например `[["ROW_NUMBER", "Решите через ROW_NUMBER."]]`. |
| `forbid: [["YEAR\\s*\\(", "Не применяйте функцию к столбцу в WHERE."]]` | Запрещённая конструкция. |

`allowEmpty: true` — эталон может вернуть 0 строк (иначе проверка выдаст замечание).

**Правила, чтобы задачи были честными:**
- Если в эталоне `TOP`, должен быть `ORDER BY`, а на границе TOP не должно быть «ничьих» (или добавьте второй ключ сортировки и опишите его в тексте).
- Все суммы и доли приводите к `DECIMAL(p,s)` и указывайте тип в тексте задачи.
- Периоды по `datetime` задавайте диапазоном: `>= '20261001' AND < '20261101'`.

## 6. tasks.json — практикум

Наборы задач, которые показываются карточками на главной в разделе базы.

```json
{ "sets": [
  { "id": "s1", "title": "Первые запросы", "short": "Подпись на карточке",
    "desc": "Вступление над задачами", "tasks": [ {задание}, {задание} ] }
] }
```
У задания практикума можно указать `level` (1–5) — тогда XP начисляется как в тренажёре; иначе как за домашнее задание.

## 7. trainer.json — тренажёр

```json
{ "tasks": [ { "id": "tr1-1", "level": 1, "title": "…", "tags": ["WHERE"], "text": "…", "solution": "…" } ] }
```
Уровни: 1 — Разминка (SELECT, WHERE, ORDER BY, TOP); 2 — Базовый (функции, NULL, даты, CASE); 3 — Средний (группировка, соединения); 4 — Продвинутый (подзапросы, CTE, множества); 5 — Эксперт (окна, сложные отчёты).

## 8. examples.json — примеры для песочницы

```json
{ "examples": [ { "title": "Последние чеки", "sql": "SELECT TOP (20) * FROM Orders ORDER BY OrderDate DESC;" } ] }
```

## 9. course.json — модули и уроки

```json
{ "modules": [ {
  "id": "m1", "title": "Название модуля", "short": "Подпись на карточке", "goal": "Цель модуля",
  "read": [["Ссылка для чтения", "https://metanit.com/sql/sqlserver/"]],
  "lessons": [ {
    "id": "l1", "title": "Урок", "minutes": 10,
    "steps": [
      { "t": "text", "title": "Теория", "text": ["Абзац", "", "- пункт"] },
      { "t": "example", "title": "Пример", "text": "Пояснение", "sql": "SELECT …;" },
      { "t": "widget", "title": "Схема", "w": "execOrder", "text": "Пояснение" },
      { "t": "quiz", "id": "q1", "q": "Вопрос?", "options": ["A", "B", "C"], "answer": 1, "explain": "Почему" },
      { "t": "order", "id": "o1", "q": "Расставьте по порядку", "items": ["первый", "второй", "третий"], "explain": "…" },
      { "t": "task", "id": "t1", "title": "Задание", "text": "…", "solution": "…" }
    ],
    "training": [ {задание или вопрос}, … ]
  } ],
  "homework": [ {задание}, … ]
} ] }
```
- `quiz`: `answer` — номер верного варианта с 0; для нескольких верных — массив `[0, 2]`.
- `order`: элементы `items` пишите в **правильном** порядке — курс перемешает их сам.
- `widget`: встроенные интерактивные схемы — `joinViz` (виды JOIN), `nullTruth` (NULL и логика), `likeViz` (LIKE), `setsViz` (UNION/INTERSECT/EXCEPT), `windowViz` (оконные функции), `dateDiffViz` (DATEDIFF), `betweenViz` (BETWEEN с датами), `groupViz` (GROUP BY), `caseViz` (CASE), `execOrder` (порядок выполнения запроса), `excelMap` (Excel ↔ SQL). Они работают на своих маленьких таблицах.
- Урок засчитывается, когда ученик дошёл до конца и решил всю мини-тренировку (`training`); модуль — когда пройдены уроки и решены задачи `homework`.

## 10. id и прогресс

Прогресс ученика хранится по `id` задач, вопросов, уроков и модулей (внутри курса к ним добавляется `id` базы). Поэтому:
- `id` должны быть уникальны внутри базы;
- после выдачи базы ученикам **не меняйте** `id` — иначе решённые задачи «пропадут». Менять текст и порядок задач можно;
- если `id` не указан, курс задаст его по номеру и выдаст замечание.

## 11. Запросы к нескольким базам

Все подключённые базы доступны одновременно, как на одном SQL Server:
- `SELECT … FROM Bank.dbo.Clients` — таблица другой базы по полному имени (`ИмяБазы.dbo.Таблица`, можно `ИмяБазы..Таблица`);
- `USE Shop;` — переключить текущую базу (в песочнице меняется и выбор базы);
- `SELECT DB_NAME()` — имя текущей базы.

Задачи базы выполняются в её собственной базе, но эталон может обращаться и к другим (например, к встроенной `Bank`).

## 12. Проверка

На странице «Базы» у каждой базы есть кнопка **«Проверить задания»**: курс выполнит все примеры и эталоны, сверит `alsoOk`/`wrong`, проверит ссылки, ключи и ответы вопросов. Исправляйте все **ошибки**; **замечания** — на ваше усмотрение.

То же из командной строки (в репозитории курса, нужен Node.js):

```bash
node tools/check-pack.js schemas/my-base     # одна база
node tools/validate-packs.js                 # все базы
node tools/sql.js my-base "SELECT TOP 5 * FROM Orders"   # посмотреть данные / результат эталона
```

После добавления или правки базы обновите `schemas/index.js` (см. п. 1), иначе на компьютерах без доступа к папке будет видна старая версия.

Частые ошибки: запятая после последнего элемента в JSON; одинарные кавычки вместо двойных в JSON; имя столбца в CSV не совпадает со schema.json; дата в формате, который не распознан; TOP без ORDER BY.

## 13. Как попросить ИИ сгенерировать базу

Самый надёжный способ — скилл [skills/sql-kurs-uchebnaya-baza](../skills/sql-kurs-uchebnaya-baza/SKILL.md) в репозитории курса: с ним ИИ сам спроектирует базу, сгенерирует данные, составит задания и прогонит проверку.

Пример запроса (можно вставить в чат с Claude вместе с этим файлом):

> Сгенерируй учебную базу для курса «SELECT с нуля» строго по формату из ФОРМАТ.md. Тематика: **[например, автосалон / поликлиника / склад / кредитный конвейер]**. 6–8 таблиц со связями, реалистичные данные на Кыргызстан (сомы, города, имена), 3–10 тыс. строк в самой большой таблице, период 2025–2026, специально оставь «ловушки» для заданий: NULL-значения, записи без пары (для LEFT JOIN), отменённые операции. Сделай `tasks.json` (4 набора по 6–8 задач от простого к сложному), `trainer.json` (по 4 задачи на каждый из 5 уровней), `examples.json` (8 примеров), `course.json` (1 модуль, 2 урока). Проверь, что каждый эталон выполняется на SQL Server и не зависит от порядка строк. Отдай архив с папкой базы.

Полученную папку положите в `schemas/` и нажмите «Проверить задания».
